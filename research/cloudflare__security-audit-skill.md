**What it is:** Cloudflare's coding-agent skill for full-repo security audits — six phases (recon → coverage-led hunting by isolated sub-agents → adversarial validation by a *different* agent → machine-readable `findings.json` checked by a zero-dependency validator → independent re-verification → target-neutral report). MIT, 19k stars in three months, the seed of Cloudflare's own vulnerability harness (blog: "Build your own vulnerability harness"). Attack-class playbooks cover web/auth, client-side, supply chain, cloud/IaC, RPC, resource exhaustion, tenant isolation, native/IPC, and AI/LLM (prompt injection, tool abuse).
**Reusable for us:** Complements the built-in `/security-review` (which only reviews the pending diff) with a repo-wide, evidence-graded audit. Best targets: tradingdesk (money-affecting logic, broker creds), language-tutor (auth'd web app), notify-bot (webhooks). The verdict discipline (`confirmed` needs a full source trace; `needs_validation` never gets a severity) matches our "trial before adopt" honesty rule.
**Token / effectiveness angle:** Expensive by design — many parallel sub-agents per phase; multiple runs improve coverage (their data: one run ≈ half the findings). Run it deliberately (pre-release, quarterly), on Sonnet-class sub-agents, never as a routine hook. Executing target code needs an OS sandbox with networking off; without one it stays in `needs_validation`, which is fine for a first pass.
**How to adopt:** `npx skills add https://github.com/cloudflare/security-audit-skill --skill security-audit --global` (installs to the user-level skills dir; Node needed for the validators). Trial on claude-notify-bot first (small), then language-tutor; append Field notes here (false-positive rate, runtime, tokens) and flip `status` to `trialed`/`in-use`. If it earns its keep, ship it fleet-wide by adding a `skills/` asset kind to the consumer sync (v1.1 candidate).
