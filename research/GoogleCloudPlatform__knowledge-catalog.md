# GoogleCloudPlatform/knowledge-catalog · ⭐7017 · watch · emerging
https://github.com/GoogleCloudPlatform/knowledge-catalog · pushed 2026-07-10 · triaged 2026-07-14 · seen on user-submitted

**What it is:** Home of **OKF (Open Knowledge Format)** — a Google-backed minimal spec for representing knowledge as hierarchical markdown files with YAML frontmatter (`type` required; `title`/`description`/`resource`/`tags`/`timestamp` optional), organized into a "bundle" with optional `index.md` (directory listing for progressive disclosure) and `log.md` (change history), cross-linked with bundle-relative links (`/path/concept.md`). Tool-free, diffable, explicitly human- and agent-readable. `okf/SPEC.md`.
**Reusable for us:** The **progressive-disclosure `index.md`** pattern is the transferable bit — an agent reads a compact index and opens only the concept files it needs, instead of loading a whole knowledge tree. The minimal frontmatter (`type`/`description`/`tags`) also overlaps cleanly with our existing asset metadata (`kind`/`intent`/`tags`).
**Token / effectiveness angle:** Progressive disclosure is a direct read-fewer-tokens lever for knowledge corpora — same principle as our "targeted reads", applied to whole reference bundles. Good fit for *knowledge* surfaces (`research/` notes, `docs/`, a project's schemas/playbooks), **not** for executable agent configs (`.claude/agents/*.md` are `name`/`description`/`tools` behavior files, a category mismatch).
**How to adopt:** Watch. If trialed later, apply to ONE knowledge surface first (e.g. an `index.md` over `research/` notes), verify `jq`/`build-index.py` still work, record Field notes, then decide. Do **not** blanket-apply OKF frontmatter to agent definitions.
